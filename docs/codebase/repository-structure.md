# Repository Structure

> **Purpose:** Provide an annotated map of the repository layout so developers know where configuration, database schemas, feature modules, shared utilities, and build artifacts live.
> **Audience:** Internal backend developers onboarding to the repository.
> **Prerequisites:** Read [Project Tour](../getting-started/project-tour.md).

## Overview

Writespace is a single-package TypeScript backend (`writespace-backend` in `package.json`). All application source code lives under `src/`, database migration artifacts generated by Drizzle Kit live under `drizzle/`, and container definitions live at the repository root. Path aliases configured in `tsconfig.json` (`@modules/*`, `@config/*`, `@shared/*`, `@db/*`) map directly to the top-level subdirectories inside `src/`.

## Root-level files & runtime directories

| Path                             | Tracked in Git?                | Purpose & Operational Rules                                                                                                                                                                   |
| -------------------------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Dockerfile`                     | Yes                            | Defines four build stages on `node:24-bookworm-slim`: base, development (`npm run dev`), builder (`npm run build`), and production (`node dist/server.js` as non-root user `node`).           |
| `docker-compose.yml`             | Yes                            | Local development Compose file starting `api`, `postgres:18-alpine`, and `redis:7-alpine` with `./src`, `./logs`, and `./uploads` bind-mounted.                                               |
| `docker-compose.prod.yml`        | Yes                            | Production Compose file starting `writespace-api:production` bound to `127.0.0.1:${HOST_PORT:-8000}:8000` with named volumes `api_logs` and `api_uploads`.                                    |
| `drizzle/`                       | Yes                            | Holds `0000_initial_schema.sql` and `drizzle/meta/`. Never edit generated snapshot JSON files manually.                                                                                       |
| `logs/`                          | Folder only (`!logs/.gitkeep`) | `src/config/logger.ts` writes rotating logs to `logs/combined.log` (max 10 MB, 5 files). Log files (`logs/*`, `*.log`) are ignored by `.gitignore`.                                           |
| `uploads/`                       | No (gitignored)                | Served statically at `/uploads` by `src/app.ts` (`app.use("/uploads", express.static("uploads"))`). Created in `Dockerfile` (`RUN mkdir -p logs uploads`) and mounted as a volume in Compose. |
| `dist/`                          | No (gitignored)                | Output directory created by `npm run build` (`tsc && tsc-alias`), containing compiled CommonJS `.js` files with resolved relative imports.                                                    |
| `restructure-writespace-docs.sh` | Leftover                       | `restructure-writespace-docs.sh` is a one-time migration script from the legacy docs layout — safe to delete.                                                                                 |

## Key decisions & rationale

- **Feature-modular layout (`src/modules/*`) over technical-layer folders:** Instead of placing all controllers in a top-level `src/controllers/` directory and all services in `src/services/`, each domain capability (`auth`, `sessions`, `users`, `posts`, `articles`, `interactions`, `notification`) encapsulates its own routes, controllers, services, DTOs, and repositories. Only cross-cutting middlewares, queues, and utilities live in `src/shared/`.

- **Excluding `test/` and `docs/` from the production build:** `tsconfig.json` excludes `node_modules`, `dist`, and `test`, and `.dockerignore` excludes `docs`, `test`, and `tests` so the production image contains only compiled runtime code under `/app/dist`.

## Gotchas & edge cases

- **Path aliases require `tsc-alias` for production builds:** Because `tsconfig.json` defines `@modules/*`, `@config/*`, `@shared/*`, and `@db/*`, running `tsc` alone emits `require("@config/env")` in `dist/`, which Node.js cannot resolve at runtime. Always use `npm run build` (`tsc && tsc-alias`) so `tsc-alias` rewrites path aliases to relative paths in `dist/`.

- **AI directories (`src/modules/ai/` and `src/shared/ai/`):** These directories exist in the repository for the planned v2 post-assistant feature and are out of scope for v1 documentation—see **[AI Integration (Gemini) — Coming in v2](../modules/)**.
