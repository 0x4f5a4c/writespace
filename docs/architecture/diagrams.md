## Diagram authoring rules

When adding or modifying a diagram anywhere in `docs/`, follow these rules:

1. **Caption line required:** Place `**Diagram: <name>**` on the line immediately preceding the ` ```mermaid ` fence.
2. **Node count limit:** Keep every diagram at or below ~15 nodes so GitBook renders labels legibly without horizontal scrolling. Split large schemas or flows into focused diagrams.
3. **Quote labels containing punctuation:** Always wrap node labels containing parentheses, slashes, colons, or spaces in double quotes inside brackets — for example, `API["Express 5 API (/api/v1)"]`.
4. **Update this index:** Every new or renamed diagram must be added to the table on this page in the same commit.

## Key decisions & rationale

- **Mermaid source over static PNG/SVG exports for architecture diagrams:** Keeping all system, ER, sequence, and state diagrams in Mermaid syntax ensures that contributors editing pages in GitBook or via Git pull requests can update diagrams alongside code changes without needing external diagramming project files.

## Gotchas & edge cases

- **No `->` arrows in `erDiagram`:** Mermaid `erDiagram` blocks require crow's-foot cardinality syntax (`||--o{`, `||--o|`, `}o--||`) and uppercase/identifier entity names without spaces.
- **Avoid reserved words as unquoted node IDs:** Do not use `end`, `subgraph`, `style`, or `class` as bare node identifiers in `flowchart` blocks.
