# Technology Stack & Rationale

> **Purpose:** Document every core technology in the Writespace stack, its pinned/configured version, where it is wired in code, and why it was selected.
> **Audience:** Internal backend developers and technical reviewers.
> **Prerequisites:** Read [Architecture Overview (C4 L1 & L2)](overview.md).

## Overview

Writespace (`package.json`) favors explicit, type-safe, and operationally predictable libraries over heavy, magic-driven frameworks. SQL queries are written through Drizzle ORM's typed query builder rather than an active-record ORM; request payloads and environment variables are validated with Zod; and asynchronous reliability is anchored in PostgreSQL (`outbox_events`, `notification_deliveries`) with BullMQ and Redis acting as the execution transport.

## Key decisions & rationale

- **Why Satori + Resvg instead of Puppeteer/Playwright for Open Graph images?** Launching headless Chromium inside a container consumes hundreds of megabytes of RAM — unacceptable on a shared ~12 GB single-VM deployment (Path A). `satori` + `@resvg/resvg-js` (`src/shared/utils/og-generator.ts`) generates 1200x630 PNG buffers in milliseconds with a tiny memory footprint.
- **Why Drizzle ORM over Prisma?** Writespace relies heavily on explicit `SELECT ... FOR UPDATE` row locks (`for("update")`), partial unique indexes with custom SQL predicates, `GREATEST`/`LEAST` SQL expressions, and `clock_timestamp()` reads inside transactions (`src/modules/notification/repositories/notification-delivery.repository.ts`). Drizzle exposes these PostgreSQL primitives directly in TypeScript without raw-query escape hatches.
- **Why custom `RedisOAuthStateStore` instead of `express-session`?** Passport's default OAuth2 state validation requires `express-session`, which introduces server-side session cookies for all routes. `RedisOAuthStateStore` (`src/modules/auth/oauth-state.store.ts`) implements `OAuth2Strategy.StateStore` directly against Redis (`oauth:state:<provider>:<sha256(state)>`) with per-flow browser-binding cookies (`oauth_state_<provider>_<state>`), supporting concurrent multi-tab OAuth logins without `express-session`.

## Gotchas & edge cases

- **`sanitize-html` is installed in `package.json` (`^2.17.0`) but Posts and Articles store structured JSONB:** Content bodies are persisted as `ContentDocument` JSONB (`src/db/schema/content-document.ts`) rather than raw HTML strings, and email/OG templates escape strings via `escapeHtml` (`src/modules/notification/templates/layout.ts`, `src/shared/middlewares/bot-interceptor.middleware.ts`). Note that `sanitize-html` in `package-lock.json` resolves to `2.18.1`, which declares `"engines": { "node": ">=22.12.0" }`.
- **Passport OAuth2 `store.length` and `verify.length` arity check:** `passport-oauth2@1.8.0` inspects `Function.prototype.length` at runtime to choose whether to pass `meta` to `store` and `verify`. As documented in `src/modules/auth/oauth-state.store.ts`, `store` must keep exactly 3 parameters and `verify` must keep exactly 4 parameters — changing their parameter count breaks OAuth state verification.
