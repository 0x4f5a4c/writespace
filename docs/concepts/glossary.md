# Glossary

> **Purpose:** Provide a single canonical definition and source reference for every domain and architectural term used in Writespace.
> **Audience:** All engineers, client integrators, and operations maintainers.
> **Prerequisites:** None.

## Overview

Writespace uses specific terminology in its database schema, services, and worker pipelines. Use the definitions below to keep code reviews, API contracts, and incident runbooks consistent.

## Canonical terms (A–Z)

| Term                               | Aliases / DB Identifier                                                    | Definition & Source Traceability                                                                                                                                                                                                                                                                                                                                            |
| :--------------------------------- | :------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Aggregate**                      | `EventAggregate`, `aggregate_type` + `aggregate_id`                        | The domain object (`CONTENT_ITEM`, `COMMENT`, `USER`, `FOLLOW_RELATIONSHIP`, `notification_delivery`) associated with an outbox event (`src/modules/notification/contracts/event-envelope.types.ts`).                                                                                                                                                                       |
| **Ambiguous Outcome**              | `outcome: "ambiguous"`, `status: "unknown"`                                | A delivery attempt state indicating that a worker lease expired or a transport connection failed after external transmission (such as SMTP `DATA`) may have begun. Ambiguous attempts resolve the parent delivery to `status = "unknown"` and are never automatically retried (`src/modules/notification/repositories/notification-delivery.repository.ts`).                |
| **Article**                        | `articles`, `content_type: "article"`                                      | A long-form technical publication with a required `title` (5–200 chars), unique URL `slug`, estimated `read_time`, optional cover image, and structured `ContentDocument` (`src/db/schema/articles.ts`, `src/modules/articles/`).                                                                                                                                           |
| **Assurance Level**                | `assurance_level`                                                          | Integer (`1..3`, default `1`) on `auth_sessions` recording the strength of authentication used to establish the session (`src/db/schema/auth-sessions.ts`).                                                                                                                                                                                                                 |
| **Auth Challenge**                 | `auth_challenges`                                                          | A time-bounded verification challenge (`registration`, `email_verification`, `password_reset`, `email_change`) storing only a cryptographic digest (`secret_hash`) of the secret (`src/db/schema/auth-challenges.ts`).                                                                                                                                                      |
| **Auth Identity**                  | `auth_identities`                                                          | A login method (`password`, `google`, or `github`) linked to a `users` account (`src/db/schema/auth-identities.ts`).                                                                                                                                                                                                                                                        |
| **Auth Session**                   | `auth_sessions`, `sid`                                                     | A server-managed login session with independent `idle_expires_at` (7d default) and `absolute_expires_at` (30d default) timestamps (`src/db/schema/auth-sessions.ts`, `src/modules/sessions/session.service.ts`).                                                                                                                                                            |
| **Browser Binding**                | `oauth_state_<provider>_<state>`                                           | An `HttpOnly` cookie storing a 32-byte random hex value whose SHA-256 hash is stored in Redis alongside the OAuth `state` parameter to prevent login CSRF and tab-clobbering (`src/modules/auth/oauth-state.store.ts`).                                                                                                                                                     |
| **Content Document**               | `ContentDocument`, `content_document`                                      | Versioned JSONB structure (`{ version: 1, blocks: [...] }`) shared by Posts and Articles, consisting of `paragraph` blocks (with `text`, `link`, and `mention` inline nodes) and `code` blocks (`src/db/schema/content-document.ts`).                                                                                                                                       |
| **Content Item**                   | `content_items`, `contentItemId`                                           | The shared parent record owning the UUID, author reference, publication lifecycle (`draft`, `scheduled`, `published`), engagement counters, and concurrency `version` for every Post and Article (`src/db/schema/content-items.ts`).                                                                                                                                        |
| **Cursor Pagination**              | Keyset Pagination, `nextCursor`                                            | Pagination strategy using Base64URL-encoded JSON tuples—such as `{ publishDate, id }` or `{ createdAt, id }` with microsecond UTC timestamps (`YYYY-MM-DD"T"HH24:MI:SS.US"Z"`)—and `limit + 1` lookahead (`src/modules/posts/services/post-query.service.ts`).                                                                                                              |
| **Dedupe Key**                     | `dedupe_key`                                                               | Unique key (`event:<eventId>:<notificationType>` or `group:<groupId>`) preventing duplicate active inbox notifications for the same recipient (`src/db/schema/notifications.ts`).                                                                                                                                                                                           |
| **Delivery Lease**                 | `locked_at`, `locked_by`, `lease_expires_at`                               | Temporary ownership lock (default `60000ms`, renewed every `leaseDurationMs / 3`) held by a `notificationDeliveryEventsWorker` while executing a channel delivery (`src/modules/notification/services/notification-delivery.service.ts`).                                                                                                                                   |
| **Denormalized Counter**           | `reaction_count`, `comment_count`, `share_count`, `reply_count`, `total_*` | Integer counters stored directly on `users`, `content_items`, and `comments`, updated transactionally under `FOR UPDATE` row locks and guarded by non-negative `CHECK` constraints (`src/scripts/seed/counters.seed.ts`).                                                                                                                                                   |
| **Destination Fingerprint**        | `destination_fingerprint`                                                  | Keyed hash of a normalized recipient address (email or push destination) in `notification_suppressions`, avoiding raw PII storage in suppression lookup keys (`src/db/schema/notification-suppressions.ts`).                                                                                                                                                                |
| **Grouping Key**                   | `grouping_key`, `grouping_window_start`                                    | Deterministic key (`post-reaction:<contentItemId>:<reactionType>`) and 5-minute UTC bucket used to aggregate multiple Post reactions into a single `notification_groups` row (`src/modules/notification/domain/notification-grouping.policy.ts`).                                                                                                                           |
| **Idempotency Key**                | `idempotency_key`                                                          | Unique string (`<channel>:<eventId>:<notificationId>`) on `notification_deliveries` ensuring at most one logical delivery record is created per channel per source event (`src/db/schema/notification-deliveries.ts`).                                                                                                                                                      |
| **Interaction Event**              | `interaction_events`                                                       | Best-effort, post-commit historical record of a reaction, follow, save, or share action (`src/db/schema/interaction-events.ts`, `src/modules/interactions/events/interaction-event.publisher.ts`).                                                                                                                                                                          |
| **Mandatory Security Alert**       | `auth.security_alert`, `SECURITY_ALERT`                                    | High-priority notification category (`security`, classification `mandatory_security`) triggered by allowlisted `security_events` (`auth.login`, `auth.oauth_login`, `password.reset`, `password.changed`, `account.suspended`, `refresh_token.reuse_detected`). Cannot be disabled by user preferences (`src/modules/notification/domain/notification-policy.registry.ts`). |
| **Optimistic Concurrency Version** | `content_items.version`                                                    | Monotonically increasing integer (`>= 1`) checked in the `WHERE` clause when updating a Post or Article; concurrent edits fail with `409 Conflict` (`src/modules/posts/services/post-command.service.ts`).                                                                                                                                                                  |
| **Outbox Event**                   | `outbox_events`                                                            | Durable domain or delivery-request event written in the same PostgreSQL transaction as the originating state change and polled by `outboxDispatcherWorker` (`src/db/schema/outbox-events.ts`).                                                                                                                                                                              |
| **Path A Topology**                | OCI Single-VM Deployment                                                   | Intended v1 production deployment running Nginx on the host and Docker Compose (`api`, `postgres`, `redis`) on a single Oracle Cloud Always Free Ampere A1 ARM64 VM (~12 GB RAM) without PgBouncer (see [Deployment Topology](../architecture/deployment-topology.md)).                                                                                                     |
| **Post**                           | `posts`, `content_type: "post"`                                            | Short-form social content item (<= 6,000 visible characters) without a title or slug, supporting up to 5 ordered image attachments in `post_media` (`src/db/schema/posts.ts`, `src/modules/posts/`).                                                                                                                                                                        |
| **Processed Event**                | `processed_events`                                                         | Composite-key `(consumer_name, event_id)` record tracking whether a logical consumer has already processed an outbox event (`src/db/schema/processed-events.ts`).                                                                                                                                                                                                           |
| **Reconciliation Lease**           | `reconciliation_locked_*`, `reconciliation_attempt_count`                  | Independent lease and counter on `notification_deliveries` used by `notificationReconciliationWorker` to repair missing or stalled BullMQ jobs without inflating external `attempt_count` (`src/db/schema/notification-deliveries.ts`).                                                                                                                                     |
| **Refresh Token Rotation**         | `rotateRefreshToken`                                                       | Security mechanism where each presentation of a refresh token consumes the current row (`consumed_at`), issues a new 32-byte token (`replaced_by_token_id`), and revokes the entire session if a consumed token is ever presented again (`src/modules/sessions/refresh-token.repository.ts`).                                                                               |
| **Trusted Origin**                 | `TRUSTED_CLIENT_ORIGIN`                                                    | The scheme+host origin extracted from `env.CLIENT_URL` and checked against `Origin` (or fallback `Referer`) by `requireTrustedOriginForCookieAuth` whenever a `refreshToken` cookie is present (`src/shared/middlewares/trusted-origin.middleware.ts`).                                                                                                                     |

## Key decisions & rationale

- **Separate terminology for `outbox_events` vs. `interaction_events`:** Keeping **Outbox Events** (transactional notification triggers) distinct from **Interaction Events** (post-commit activity history) prevents developers from treating best-effort analytics rows as reliable message-queue inputs.
- **Explicit distinction between `"accepted"` and `"delivered"`:** In `notification_deliveries` and `mailer.ts`, SMTP `250 OK` and Socket.IO room emission are recorded as `outcome: "accepted"` (`accepted_at`), because transport acceptance by an SMTP relay or WebSocket server does not prove end-user inbox or browser rendering (`confirmed_delivered_at`).

## Gotchas & edge cases

- **`postId` in legacy interaction routes vs. `contentItemId`:** Several routes in `src/modules/interactions/interactions.routes.ts` (such as `/interactions/comments/:postId`, `/interactions/posts/:postId/reaction`, and `/interactions/posts/:postId/save`) retain the parameter name `:postId` for backward compatibility, but `InteractionsService` passes that UUID directly to `contentItemId` methods (`src/modules/interactions/interactions.service.ts`). Only `saveService.savePost` and `shareService.createShare` explicitly assert that the target subtype is `"post"`.
